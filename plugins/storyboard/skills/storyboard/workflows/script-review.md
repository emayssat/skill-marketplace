# Script Review (Before Any Boarding)

**When to use:** A script or draft exists, no boards do, and you want it critiqued before committing anyone to boarding it. This is the cheap gate — a script problem costs an afternoon here and a week once forty frames have been drawn against it.

Deliberately much lighter than **New Storyboard Creation**. If it passes, pick that workflow up from step 6.

**Inputs required:** A script draft. Ideally a production brief or at least a project type for the target duration and audience — without one, there's nothing to measure "too long" against.

**Arc:** the other thing to catch here. Ask whether the emotion is *supposed* to change beat to beat, and whether the writing gives a performer anywhere to go — uniform sentence length and hedged clauses read fine silently and drone aloud. Flat writing is a script finding, not a delivery problem.

**Story:** the cheapest place in the whole skill to catch a structure problem, and the only place where fixing it costs a rewrite rather than a reshoot. Sasha Script names the structure and the purpose of each beat; then read the purposes top to bottom. Three beats with the same purpose is one beat. A promised stage that never arrives — a journey with no threshold, a before-after with no bridge — is why a finished piece feels unsatisfying while every frame looks fine.

**Pace:** this is the cheapest place to catch density. Report wpm per beat, not for the piece, and give all three options — cut words, stretch the beat, or change the target — because at script stage every one of them is still free.

## Sequence

| # | Persona | Task | Output / gate |
|---|---|---|---|
| 1 | scriptwriter | State the intended beat structure and target duration, and note anything already known to be shaky | Draft + stated intent |
| 2 | voice-talent | Read it aloud. Report words-per-minute **per beat** against the seconds that beat has — ~150 wpm comfortable, over 170 unusable — and flag unspeakable lines | Read-through notes + per-beat wpm |
| 3 | director | Assess shot potential beat by beat: does each one suggest a picture, or is this radio with visuals stapled on? | Shot-potential verdict |
| 4 | *1-2 audience personas* | The primary personas from the brief react to the script read aloud — does the message land, and where do they drift? | Per-persona reactions |
| 5 | legal-reviewer | Flag claims needing substantiation now, while a rewrite is still cheap (skip if internal-only) | Early claims list |
| 6 | scriptwriter | Revise against all of the above | Revised script |
| 7 | producer | Decide: proceed to boarding, or another script pass? | Go to boarding / another pass |

## Final output

A revised `script.md` and an explicit decision about whether it's worth boarding — plus, if it passes, a read time you can trust.

## Notes / anti-patterns

- Step 2 kills more scripts than step 3 does, and it's the step teams skip. A script that reads beautifully and runs 40% long is not a good script yet.
- Check pace **per beat, not per piece.** A 2:00 script can average a comfortable 140 wpm while one 8-second beat carries 30 words. The average hides exactly the problem you need to find.
- Step 3 is the expensive-failure gate: "radio with visuals" is cheap to fix in a script and ruinous to discover at frame 30. If Dana Director can't picture a beat, that's a finding, not a style preference.
- Don't run the full premiere panel here. Two personas reacting to a script read aloud is proportionate; ten is a preview round against material that isn't ready for one.
- Getting Logan Legal in at step 5 is unintuitive but cheap — pulling an unsupportable claim from a paragraph costs nothing compared to pulling it from a scored animatic.
