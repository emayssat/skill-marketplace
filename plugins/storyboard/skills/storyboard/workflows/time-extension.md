# Time Extension (Lengthen an Existing Storyboard)

**When to use:** An existing (approved or in-progress) storyboard needs to grow to a longer runtime — e.g. 2:00 to 3:00 — while keeping the same core story. Distinct from a remake (content refresh) and a redesign (visual-only): here the actual runtime and content grow.

**Inputs required:** The current approved (or draft) script and boards, plus the new target duration.

**Pace:** extra runtime is the chance to fix density you were already living with. Before adding new material, re-run `--pace` on the existing beats — if any were over the ceiling, spend some of the new time there first. Adding content while leaving a rushed beat rushed makes the piece longer *and* still bad.

**Cards:** extra runtime tempts everyone to pad with motion. Added seconds should go to pauses, held beats and breathing room before they go to new builds — a longer piece full of movement is not slower, it's busier. Where a frame gains time and nothing new happens in it, say `STILL — <reason>`. New frames get new numbers (`11a` between 11 and 12), and each arrives as a finished card: Text if it carries any, Trans only if the join isn't a cut, a Note if something changes there. The extension itself is a Revision log row naming the new frames — not a Note on each one saying it was added.

## Sequence

| # | Persona | Task | Output / gate |
|---|---|---|---|
| 1 | producer | Confirm the new target duration and where the added budget/schedule comes from | Confirmed scope |
| 2 | director | Decide where the added time goes — a new beat, an expanded existing beat, or added depth somewhere specific; must protect pacing, not just pad runtime | Extension plan |
| 3 | scriptwriter | Write new lines/scenes for the added beat(s), consistent with the existing script's voice | New script pages |
| 4 | storyboard-artist | Board only the new/changed frames; existing frames carry over unchanged | Updated board pass |
| 5 | art-director | Extend style references only if new content needs locations, props, or UI not seen before | Updated references (if needed) |
| 6 | dp | Feasibility check on the new shots only | Feasibility notes |
| 7 | editor | Re-cut the animatic inserting the new material; re-check overall pacing now that runtime changed | Updated animatic |
| 8 | sound-designer | Extend or compose additional music and sound design to cover the new material, blending seamlessly with the existing score | Extended mix |
| 9 | producer | Update schedule/budget to reflect the added shots | Locked schedule + budget |
| 10 | client | Approve the addition specifically — what's new and why it's needed | Approved extension |

## Final output

The same core story at the new target duration, with the added material integrated into script, boards, and animatic.

## Notes / anti-patterns

- Step 2 is the workflow's real gate: added time should come from a genuine story or proof need, not from stretching existing beats to fill a runtime number.
- A pacing check (step 7) matters more here than in a fresh build — adding a good beat in isolation can still break the overall rhythm of a piece that was tuned for a shorter runtime.
- If the "extension" turns out to require rethinking the whole arc rather than adding to it, that's closer to **New Storyboard Creation** than this workflow.
