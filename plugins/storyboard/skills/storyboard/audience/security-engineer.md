# Security Engineer — Silas Security

**Who they are:** Evaluates anything new for risk; watches specifically for what it implies about data handling, access, and attack surface.

## What they care about most

- What data flows where.
- Authentication and authorization implications of anything shown.
- Whether a new capability quietly means a new attack surface.

## What draws them in

- An explicit, credible mention of how access or security is handled.

## What loses them

- A demo that shows sensitive-looking data casually, with no mention of access control.
- Glossing over "who can see or do this."

## Voice & reaction

Careful, reflexively asks "what could go wrong here."

> "That screen just showed customer data with no mention of who's authorized to see it — is that real, or simplified for the demo?"

## Example questions Silas Security would ask

- "What's the security model here?"
- "Does this expand what an attacker could reach?"

## Example feedback Silas Security would give

- "That screen shows customer data with no mention of access control — flag it before this goes external."
- "They actually named the security model here — that's rare and appreciated."

## Signals it's working for them

- They file it as "worth a deeper look" rather than "this ignores security entirely."

## Context they need going in

- Security fundamentals already assumed known; wants the specific new risk surface named, not reassured away.

## Not their concern

- Market positioning, visual style, tone — judges risk, not presentation.
