# 2-Minute Product Vision

**Goal:** Get leadership, cross-functional stakeholders, and early prospects excited about where the product is headed — before the thing fully exists.

**Audience:** Internal leadership review, sales/marketing stakeholders, and select prospects or design partners seeing an early concept.

**Key message:** There's a specific, currently-painful problem, and this product's future direction solves it in a way nothing today does.

**Tone:** Aspirational, confident, a little bit "of course it should work this way" — not a feature list.

## Story structure (default)

**before → after → bridge** — a vision piece has to make the new world credible *and* say how anyone reaches it; the bridge beat is the one most often dropped.

Sasha Script can deviate, but says so in the brief and says why. The beat breakdown below is this structure's stages named for this format; changing the structure changes the beats.

## Beat breakdown

| Time | Beat | What happens |
|---|---|---|
| 0:00–0:15 | Hook | Cold open on the status quo — the friction/pain, shown concretely (a real workflow, a real frustration), no narration yet or a single sharp line. |
| 0:15–0:35 | Reframe | Voiceover names the problem plainly and pivots: "What if instead..." Introduces the big idea in one sentence. |
| 0:35–1:25 | Vision in action | The core sequence: concept UI / product-in-use moments showing the vision realized, 2–3 key "aha" moments, each building on the last. |
| 1:25–1:45 | Impact | Zoom out from feature to outcome — what changes for the user/business once this is real. |
| 1:45–2:00 | Close / CTA | Brand moment, one clear next step ("Join the early access list," "Talk to us"). |

## Team for this project

- **Scriptwriter** — writes the narration line-by-line; this format lives or dies on the voiceover script, so gets more weight than usual.
- **Director** — owns the reframe-to-vision arc; makes sure beat 3 doesn't drift into a feature demo.
- **Storyboard artist** — boards concept UI screens and transitions rather than live blocking.
- **Art director / Production designer** — heavier than usual: defines the UI/motion visual language since there's no real set or location.
- **Cinematographer / Director of Photography (DP)** — light or replaced by a **Motion/Animation lead** if fully motion-graphics; stays on as DP if any live-action b-roll is mixed in.
- **Editor** — critical for pacing the "aha" moments; first to flag if beat 3 runs long.
- **Producer** — tracks turnaround on motion graphics/animation, often the longest lead-time item.
- **Client / stakeholder** — usually product leadership or product marketing; approving against strategic narrative, not brand compliance.

## Deliverables checklist

- [ ] Locked script (voiceover)

## Constraints specific to this project

- Nothing shown can promise a shipped feature that isn't at least directionally real — legal/PR risk if this leaks or gets quoted as a roadmap commitment.
- Keep it demo-agnostic enough that it still holds up if the actual UI changes before ship.
